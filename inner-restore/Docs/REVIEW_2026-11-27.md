# INNER RESTORE 第三者レビュー（2026-11-27）

制作に関わっていないレビュアーによる採点。PROMPTS「全体の完成度を上げたいとき」の手順に従う。

## 0. 確認の方法と限界（先に正直に書く）

- **見たもの**：全21区域の開始時スクリーンショット（960×540、HUD 表示は「WebGL 2・互換」段階、健康度 0%）、締めくくりの静止画6枚、図鑑画像12枚、参考写真12枚（heart／brain／compare）、`GAME_BRIEF.md` の基準、`src/pages/main.ts`・`src/game/ui.ts`・`src/ui/ui.css`・`src/core/{post,realism,audio}.ts`・各ステージの光と霧の設定。
- **見ていないもの**：動いている画面、WebGPU／PC 高画質（被写界深度・ブルーム・影・AO）の絵、回復していく途中の絵、音の実際の聞こえ方、VR の実機。したがって「操作」「音」「VR」はソースからの判断で、**実機で確かめたものではない**。
- スクリーンショットは「互換」段階なので、PC 高画質ではブルーム・DOF・影が上乗せされる。ただし GAME_BRIEF は「基本の見た目は WebGL 2 でも成り立つように作る」としているので、この絵を土台として採点した。
- 明るさは画像から実測した（画面下 2/3 の平均輝度と、暗いほうから 5% の画素値。下の表）。

| 区域 | 平均輝度 | 下位5%の画素値（0〜255） |
|---|---|---|
| retina／lens／cilia／mucus／olfactory | 0.65／0.60／0.71／0.70／0.67 | 145／130／149／144／150 |
| bronchiole／alveolus／alvwall | 0.71／0.78／0.68 | 144／150／137 |
| villi／colon／crypt | 0.64／0.67／0.64 | 136／148／143 |

21区域のうち18区域で、**画面にほぼ「黒」が存在しない**（最も暗い画素でも中間の灰色）。これが全体の安っぽさの最大の原因である（後述）。

## 1. 最初の5分で感じる「安っぽさ」と「待たされ感」10個

1. **最初の画面（retina.png）が、ベージュの砂丘にしか見えない。** 血管も赤血球も細胞も画面に入っていない。HUD は「血流の回復」と言うが、血が1滴も見えない。体の中だと分かる手がかりが、最初の1枚にない。
2. **全区域が、霧のかかった明るいパステル色。** 上の表のとおり暗部がない。GAME_BRIEF「体の中は本来まっ暗」「暗部を恐れない映画的な露出」「均一な照明を残さない」に正面から反している。photo（視細胞）と myo（心筋）だけが別のゲームのように良い。
3. **主人公が、つやつやの紫のフィギュアに見える。** 全21枚で同じ「腰に手を当てた立ち姿」。指示は「硬質な素材のスーツ」だが、ラテックスの人形の質感で、医療・科学の重さがない。画面の中央に常にいるので、作品の格をここが決めてしまっている。
4. **開発用の表示が本番に出ている。** 右下の「WebGL 2・互換・PC・0 fps 解像度 ×1.00」、タイトルの「実機診断」「進捗」リンク。
5. **画面下に、操作説明の全文が1行で出続ける**（`#hint`、0.82em）。チュートリアルではなく説明書の貼り付け。
6. **HUD が重なり、読めない。** 上中央の3ボタンが左上の区域名に重なる（olfactory.png「においを感じる力の回復」、scar.png）。脳の3区域では右上の窓の見出しが2行に折れて波形に重なる。左上の白い文字は、明るいベージュの背景で沈む（retina.png の区域名はほぼ読めない）。
7. **区域を治すたびに、止められない約17.5秒 → ページ全体の読み込み直し → タイトル画面 → 「つづきから」をもう一度押す。** `finish()` は 4.5 秒＋13 秒の固定タイマーで、飛ばす手段がない。「次の区域へ」は `location.href` で丸ごと再読込し、描画エンジンの初期化とシェーダーの準備をやり直す。21区域で20回これが起きる。
8. **読み込み中の豆知識が4つだけで、全部「目」の話。** 肺や脳を読み込んでいても網膜の話が出る。進み具合の棒は 10%→30%→70%→100% の4段跳びで、30% と 70% で止まって見える。
9. **球・円柱・円錐がそのまま見える。** 鼻と肺の黄土色の球の房（cilia／mucus／bronchiole）、弁の円錐台（valve.png 上）、腸の細菌のカプセル（villi／colon）、神経細胞の円錐＋パイプ（cortex.png）、アミロイドのつるつるの球（amyloid.png）。GAME_BRIEF「基本図形のままの仮モデルを残さない」に反する。
10. **右上の「患者の変化」が、7器官とも同じ病室の窓の写真。** その上に波線や横棒を重ねているだけ。腸の「おなかの痛み／食欲」の横棒は、業務アプリの進捗バーに見える。最大のごほうびのはずの場所が、最も使い回しに見える。

（次点）区域の端に来ると「区域の端です」のトーストで止められる見えない壁／設定を変えるとページを読み込み直す／紹介カードの後に固定6秒の間。

## 2. 評価の高い Web 3D・VR 作品、AA 級タイトルと比べて足りない点

### 映像
- **露出と光**：各ステージで `HemisphereLight` が 0.7〜0.9、霧の色が 0x9a7470 前後と明るく、`post.ts` はさらに黒を持ち上げている（`g.mul(0.96).add(vec3(0.018,0.01,0.006))`）。結果、探照灯（`realism.ts` の PointLight、強さ10）が絵にまったく効いていない。光源が見えない絵には奥行きが出ない。
- **濡れ・透け・屈折が見えない**：粘膜のはずの床がどれも粉っぽい艶消し（cilia／olfactory／villi／crypt／endo）。濡れた照り返しが見えるのは scar.png の巨大なハイライトだけで、これは逆にプラスチックのソーセージに見える。
- **床の使い回し**：ボロノイ模様の床が villi／crypt／bbb／cortex／amyloid で同じ。valve／clot／endo はサーモンピンクの床＋赤血球の影で、ほぼ同じ絵。mucus と bronchiole は同じ白い塊と黄土色の球で、区別がつかない。「同じ遊びの色違いにしない」は、絵でも守られていない。
- **破綻**：
  - myo.png：主人公が膝まで床に沈んでいる。白い線維が平たいリボンで、先が三角のトゲになり、面がちらついている。
  - scar.png：開始時に主人公が画面に映っていない（手前の物に隠れている）。
  - amyloid.png：球の表面に、四角く色の違う領域が見える（テクスチャの継ぎ目か、貼り付けの四角）。
  - colon.png：床の板の端が、画面中央にまっすぐな線として見える。
  - alveolus.png：手前の白い塊が画面の左下 1/3 を白く飛ばし、主人公が霧の中に消えている。
  - plaque.png：プラークの模様が引き伸ばされて、ぼやけている。
- **群れがない**：赤血球が流れる絵が、血管ステージの開始画面でも数個。指示は互換でも数千。

### 再現の正確さ（参考写真との比較）
- **線毛**（`compare/lung_bronchiolar_epithelium3_sem.jpg`）：実物は細胞ごとの房が密に立ち、間に線毛のない細胞のドームが見える。cilia.png の開始画面では線毛が「床の縞模様」にしか見えない。締めくくりの静止画（ending/cilia.jpg）では立体の線毛が見えるが、**主人公（2µm）の腰ほどの高さ**で、HUD の「線毛の長さ 約6µm」（＝身長の3倍）と合わない。要確認。
- **絨毛**（`compare/gut_chick_ileum_villi_sem.jpg`）：実物は指や葉の形の突起が林立する。villi.png は平らなサーモン色の丘で、「絨毛の草原」が見えない。おそらく1本の絨毛の上に立っているが、隣の絨毛が画面にないので伝わらない。
- **血栓**（`compare/vessel_blood_clot_sem.jpg`）：実物はフィブリンの網に赤血球が絡め取られた密な塊。clot.png の開始画面には網が見えず、valve.png と見分けがつかない。図鑑の fibrin は糸の毛玉で、赤血球が絡んでいない。
- **内皮**（`compare/vessel_endothelium_sem_larionov.png`）：実物は流れの向きに細長い敷石。valve／clot の床は放射状の筋で、敷石の輪郭が見えない。
- **心筋**（`heart/cardiac_muscle_long_200x_bcc.jpg`）：実物は枝分かれする線維と細かい横紋、介在板。myo.png は横紋が読めず、白いコラーゲンが主役になっている。scar.png の心筋は枝分かれのない腸詰め形。
- **腱索**（`heart/gross_chordae_papillary_openstax.jpg`）：endo.png には、扇状に張る細い白い腱の印象がない。
- **アミロイド斑**（`brain/cm_abeta_tau_ad_tulemo.jpg`）：実物は芯と、ぼやけた線維の暈（かさ）。周りに変形した神経突起。amyloid.png は輪郭のはっきりした、つるつるの球。
- **神経細胞・アストロサイト**（`brain/wc_astrocyte_sem.jpg`）：実物の突起は細く、先へ行くほど細かく枝分かれする。cortex.png は同じ太さのパイプ。また、**脳の実質に「床」はない**（突起がすき間なく詰まった組織）。ボロノイの床の上を歩く絵は、実物の姿から最も遠い。
- **スケール**：photo の茶色い柱は主人公の 1〜1.5 倍の高さ。桿体の外節なら太さ約2µm・長さ数十µm（身長の10倍以上）のはずで、何を表す柱なのかが絵から分からない。要確認。
- **色**：全体のベージュ／サーモンは「生体の色」としては妥当な方向。ただし光がないので、内視鏡の映像の「濡れた赤みと深い影」にならない。HANDOFF の既知の問題にある「赤血球1個の色が濃すぎる」は、図鑑の rbc.jpg でも未修正（真っ赤な不透明の樹脂）。

### 操作（ソースから。実機では未確認）
- 浄化は「画面の中心が指す床の一点」を治すだけで、対象（細胞・血栓・沈着物）を狙う手応えがない。21区域とも「床を照らして％を上げる」に見える。
- 浄化中は歩く速さが 0.265 倍になる。広い床を塗る作業で常に鈍足になり、だるさの原因になりうる。
- 区域の端は固定の四角い枠（`pos.x` の clamp）＋トースト。地形で自然に止める工夫がない。
- 常時のカメラの揺れ（`sway`）とピントの前後は、50インチでは「細かい振動を避ける」に触れる恐れ。実機で確認を。

### 音（ソースから。聞いていない）
- 持続音の和音表は全器官で同じ（`audio.ts` の `tones`。コメントも「目の主題」のまま）。「器官ごとに音色の主題を変える」は、区域ごとの環境音ファイル（約125KB）だけに頼っている。
- 心拍・当たり・チャイム・回復はすべてサイン波。「粘り、膜、泡、電気信号」の素材感がない。
- 無音の動作：足音、泳ぎ、着地、スキャンの発信、UI のボタン、紹介カードの開閉、区域の端。
- 画面版に定位（パン）がない。心拍と環境音はフィルターを通らず `master` に直結で、病気のときの「くぐもり」が心拍にかからない。

### 演出
- 回復の瞬間：`health.setAll(1)` で一気に治し、4.5秒後に病室の写真が全画面になる。「カメラを引いて全景を見せる」がない。治した組織を見せる時間より、写真を見せる時間のほうが長い。
- 締めくくり：自分のスクリーンショット6枚のスライドショー（1280×720 の JPEG を全画面に引き伸ばし）。6枚中5枚が明るく白っぽく、最後の絵として弱い。
- タイトル：放射状のグラデーションに文字だけ。後ろで 3D が描かれているのに、ほぼ不透明の幕で隠している。

### UI
- 上記 4・5・6 に加えて：HUD の「知覚加速 ×200（体内の時間をゆっくり見ています）」「潜行士の身長 2µm ／…」が常時2〜3行、左上を占める。知りたいのは最初の数秒だけ。
- 紹介カードは右下、診断は左、字幕は中央下、ヒントは最下段、窓は右上、ボタンは上中央。960px 幅では画面の四辺がすべて UI で埋まる。「スーツのバイザー表示として世界になじませる」意匠（枠・角・共通の線）がなく、ばらばらの黒い箱に見える。
- 上中央のボタンは四角い濃灰色の箱で、Web サイトのボタンそのもの。

### 読み込みの軽さ
- **良い点**：初回の JS は圧縮後 約36万バイト、モデル 9.4MB、声は1文ずつ後読み。予算には余裕がある。
- **悪い点**：区域ごとの全ページ再読込で、その軽さを捨てている。次の区域の先読みもない。進み具合の棒が実際の進みと連動していない（4段の固定値）。豆知識が4つ。

### VR の快適さ（ソースから。実機では未確認）
- バイザーの枠、移動中の暗幕、スナップ回転、フォビエーションは実装済み。ここは指示どおり。
- 懸念：(1) HANDOFF のとおり実機での fps・酔いは一度も確かめられていない。(2) 画面版でこれだけ霧が明るいと、VR では視野全体が明るい面で埋まり、目が疲れ、奥行きの手がかりが減る。暗い背景＋手元の光のほうが VR では楽で、立体感も出る。(3) 半透明の粒 110 個＋霧＋半透明の膜の重ね描きは Quest 3 で要計測。(4) 画面版で主人公が床に沈む（myo）・開始時に物に埋まる（scar）区域は、VR では頭が物の中に入る形で起きる可能性があり、強い不快感になる。

## 4. 上位5個の具体的な直し方

### ① 露出と光：「暗い体内＋手元の光」にする

- **どこ**：`src/data/tuning.json` に `look` を足し、`src/core/realism.ts`（`addRealism`）と `src/core/post.ts`、`src/pages/main.ts`／`src/pages/vr.ts` の `stage.update` の直後。
- **何を**：
  1. `tuning.json` に `"look": { "hemiScale": 0.3, "sunScale": 0.55, "fogDim": 0.3, "bgDim": 0.15, "lamp": 38, "lampRange": 30 }` を置く（初期値。撮り直しながら詰める）。
  2. `addRealism` の中で `scene.traverse` し、`HemisphereLight` の強さに `hemiScale`、`stage.sun` に `sunScale` を掛ける。探照灯を `new THREE.PointLight(0xfff2e4, look.lamp, look.lampRange, 2)` にする。
  3. 各ステージは毎コマ `scene.fog.color.setRGB(...)` と `scene.background` を書き直しているので、`stage.update(dt, t, camera)` の**直後**に共通の関数 `applyLook(scene)` を呼び、霧の色に `fogDim`、背景に `bgDim` を掛ける。毎コマ書き直さないステージがあれば二重に掛かるので、7ステージの `update` を1つずつ確かめ、書き直していない所は初期値を一度だけ暗くする。
  4. `post.ts` の色調：`g = g.mul(0.96).add(vec3(0.018, 0.01, 0.006))` の持ち上げを `vec3(0.004, 0.002, 0.001)` まで下げ、中間の灰色（0.18）を軸にコントラストを 1.12 倍、彩度の係数を 1.04 → 1.12 にする。
  5. 回復に合わせて明るくする：`hemiScale` を「0.3 ＋ 0.35 × 区域の進み」にし、治すほど光が満ちるようにする（これで「治すと生き返る」が明るさでも伝わる）。
- **目標の絵**：photo.png と myo.png の暗さを全区域の基準にする。開始時（0%）の平均輝度 0.18〜0.30、下位5%の画素値 30 以下。主人公の周り半径 10µm ほどが探照灯で明るく、濡れた面に点の照り返しが出て、遠くは暖かい闇に溶ける。治りきった時でも平均 0.45 を超えない。
- **確かめ方**：同じ21枚を撮り直し、上の表と同じ実測で比べる。VR 版（`vr.ts`）にも同じ係数を掛ける。

### ② 区域の切り替えの待ち時間をなくす

- **どこ**：`src/pages/main.ts` の `finish()`、`$('b-next').onclick`、`begin`、開始まわり。`src/game/ui.ts` の `TIPS`。
- **何を**：
  1. `finish()` の2つの `setTimeout`（4500ms・13000ms）を、名前の付いた関数 `showPatient()`／`showDone()` に分ける。患者の窓が全画面になって2秒たったら「E／タップ：次へ」を出し、押されたらすぐ `showDone()` を呼ぶ（残りのタイマーは `clearTimeout`）。
  2. 「次の区域へ」は `?zone=<id>&go=1` へ進む。読み込み後、`Q.has('go')` ならタイトルを出さずに `begin()` を呼ぶ。読み込み中は黒い幕（既存の `#fade`）の上に「次の区域：○○」と、その器官の豆知識を出す。
  3. 音は、`begin()` の後で `audio.ctx.state === 'suspended'` なら、最初の `pointerdown`／`keydown`／ゲームパッドの入力で `audio.start()` と `canvas.requestPointerLock()` を呼び直す（Safari は再読込後に音が止まるため。字幕で「画面を押すと音が出ます」と1回だけ知らせる）。
  4. `finish()` の時点で、次の区域のファイルを先読みする：`SZS[si + 1]?.load()` を呼ぶ（import の結果がキャッシュに入る）。
  5. `TIPS` を器官ごとに5つ以上に増やす（`ATLAS` の確認済みの文から作る。新しい事実は書かない）。`ZONES[zi].stage` で出し分ける。
- **目標**：100% になってから次の区域で動けるまで、飛ばせば 8 秒以内。タイトル画面は、URL を開いた最初の1回だけ。

### ③ 開始位置と向きを見せ場に向け、目に見える破綻を直す

- **どこ**：各ステージの `start: { pos, yaw }`（例：`src/stages/eye/retina.ts` 393行）、`src/stages/heart/*`、`src/stages/brain/*`、`src/stages/gut/villi.ts`、`src/stages/lung/alveolus.ts`。
- **何を（開始の構図）**：開始時の画面の中央 1/3 に、その区域の主役が入るよう `pos` と `yaw` を変える。
  - retina：赤血球が詰まった毛細血管が正面 10〜15µm に見える向き。
  - cilia：締めくくりの静止画（ending/cilia.jpg）と同じ、線毛のじゅうたんの中。
  - villi：絨毛のふもとから、隣の絨毛を2〜3本見上げる位置。
  - clot：フィブリンの網が正面に来る向き。
  - olfactory／alvwall／colon：いまは何もない面を向いているので、嗅細胞の線毛／毛細血管の網／細菌の群れのほうへ向ける。
- **何を（破綻）**：
  - myo：主人公が膝まで沈む。`floorHeight()` と見えている面の高さのずれを直す（面の変位と同じ式を `floorHeight` に入れる）。白い線維は、三角のトゲになる端を切り、厚みのある管にするか、法線を滑らかにする。
  - scar：開始時にカメラと主人公の間に物が入る。開始位置をずらすか、カメラが物にめり込むときは距離を縮める処理を足す（`tmp` を決めた後、主人公からカメラへ `stage.floorHeight` と `stage.collide` で確かめる）。巨大なハイライトは、粗さを 0.35 以上に上げて広げる。
  - amyloid：球の四角い色違いを消す（テクスチャの折り返し設定か、貼り付けの板）。
  - colon：床の板の端を、霧か地形の起伏で隠す。
  - alveolus：手前の白い塊の明るさを下げ、開始位置を塊の上か横にする。
- **目標**：21区域すべてで、開始の1枚が「どの器官の何を治すのか」を絵だけで伝える。確かめは同じ21枚の撮り直し。

### ④ HUD の掃除

- **どこ**：`src/ui/ui.css`、`src/game/ui.ts`、`src/core/hud.ts`、`src/pages/main.ts`。
- **何を**：
  1. 開発表示：`.ir-hud` は `?debug` のときだけ表示。タイトルの「実機診断」「進捗」は設定画面の末尾へ移す。
  2. ヒント：`#hint` は開始から 20 秒で薄れて消す。以後は、その操作が初めて必要になった時に1つずつ出す（例：初めて病巣に近づいたら「左クリック長押し：浄化」）。一時停止の画面に全操作の表を置く。
  3. 重なり：`#topbtns` を上中央から、右上の窓の下（右寄せ）へ移すか、PC では消して Tab／Esc に任せる（タッチのときだけ出す）。`#hud` は `width:min(40vw,20em)` に `white-space:nowrap; overflow:hidden; text-overflow:ellipsis` を `.lab` に付ける。`#patient .cap` は `white-space:nowrap`、長い見出し（脳）は「患者の脳波」に短くし、反応は波形の上の文字に任せる。
  4. 読みやすさ：`#hud` の後ろに、左上から広がる薄い暗幕（`background:linear-gradient(135deg,#000a,#0000 70%)`）を敷く。①で画面が暗くなれば、これは薄くてよい。
  5. 常時の説明：`#hud .small`（知覚加速・大きさ）は開始 12 秒で薄れ、スキャン中だけ再表示する。
  6. 意匠：窓・カード・診断・ボタンの枠を1つの決まりにそろえる（1px の `var(--acc)` の左線、角に短い鉤、背景 `#070c0ed9`）。
- **目標**：遊んでいる間、画面に出ているのは「左上の％」「右上の窓」「照準」だけ。960px 幅でも、文字と文字が1か所も重ならない。

### ⑤ 主人公を硬質なスーツに直す

- **どこ**：`src/game/diver.ts` 70〜88行（材質）と、待機の姿勢（アニメーションの選択、または `tools/` の主人公のスクリプト）。
- **何を**：
  1. 本体（72〜74行、78〜81行）：紫を掛けるのをやめ、明るい灰白（`0xd8dde0`）と濃い灰（`0x2a3036`）の2色に。`roughness` 0.16／0.24 → 0.42〜0.5、`clearcoat` 1／0.85 → 0.25、`sheen` は 0 に。縁の発光（`emissiveNode`）は係数 0.55〜0.6 → 0.12 に下げる。
  2. 差し色：光るのは、ヘルメットの縁・手の道具・背中の細い線だけにし、色は UI と同じ `--acc`（`0x7fe0d2`）にそろえる（画面の UI と主人公が同じ装備だと伝わる）。
  3. バイザー（83〜85行）：黒い鏡面のまま、反射だけ残す。

  5. ①とあわせて、探照灯の光が主人公の背中と肩に当たって見えるようにする（いまは周りが明るすぎて、主人公が自分で光っているように見える）。
